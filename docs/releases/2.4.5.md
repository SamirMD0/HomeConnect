# HomeConnect 2.4.5

A second dashboard speed fix. No migrations, no phone app change.

## Fixed

- **The same data was read many times for one dashboard page.** With every branch selected, the overview, customer and alerts cards each recalculated the same customer figures, once for all branches and once per branch. Reads already running for the same figures are now shared, and the shop-wide product list is read once instead of for every card and branch. Nothing is kept after a read finishes, so figures are never older than the request.
- **Converting timestamps to shop dates was still the largest CPU cost.** All timestamps within the same quarter hour fall on the same shop date, so each quarter hour is converted only once.
- A branch breakdown now calculates the total and each branch side by side instead of one after the other.
- Measured on a restored copy of a shop backup with every branch selected, the whole dashboard (month-end included) went from about 1.2 seconds in 2.4.4 to about 0.7 seconds on the development laptop. A slower shop PC takes longer, in proportion.

## Not changed

- Figures, totals and per-branch breakdowns are calculated exactly as before.
- No database changes.

## Operator checklist

1. Install desktop **2.4.5**.
2. Open the dashboard with all branches selected and wait for every card.
3. If it still feels slow, open **Maintenance → Open logs folder** and send `combined.log`; it records how long each request took, without customer names.

## Verification

- 756 tests in the dashboard, financial, reports, branch and sync areas pass when run one file at a time, as CI runs them. A new test checks the quarter-hour date cache against an independent formatter across a full year, daylight-saving changes and a half-hour timezone.
- Not verified: timing on the shop PC itself.
