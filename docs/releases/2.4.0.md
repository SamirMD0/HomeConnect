# HomeConnect 2.4.0

This release goes with **Home Connect phone app 2.3.0 (Android versionCode 13)**, installed as a new native APK. Phones can read a saved copy of shop data and queue supported work over the internet while the shop PC remains the authority for stock, money and permissions. Shop-Wi-Fi mode continues to work.

## New

- **Phone cloud sync:** an administrator configures the relay, creates and copies a worker secret and its Render SHA-256 without commands, enables sync, and checks Last sync in Settings. Pair a phone by user and branch, view its PIN/last-unlock status, or revoke it.
- **Offline phone records:** products, customer financial summaries, orders, suppliers and bill metadata are saved locally. Home, receivables and report figures are built by the PC and show their snapshot time. Product/bill images and some histories still need the shop Wi-Fi.
- **Cloud actions:** customer payments, supplier payments, orders and bill photos are queued durably. Waiting shows the PC's result; actions keep their original IDs across retries. Applied customer payments carry their receipt for the phone's existing share/print flow. Stock writes, customer/prepaid creation and supplier-invoice writes remain Wi-Fi-only.
- **Phone privacy:** mandatory PIN setup, optional enrolled biometrics, cold-start/timed locking, retry delays and reset after ten failed PINs. Durable cloud data, queued photos and drafts use SQLCipher; a reset preserves encrypted unsent-action summaries for review after re-pairing.
- **Recovery:** interrupted copies resume, restored PCs replace relay snapshots without ghosts, long-offline phones re-copy after the deletion horizon, and role/branch changes remove records the device may no longer receive.

## Migration notes

The following PC migrations are new since 2.3.0. They are additive or replace sync functions; none drops a shop table or column. They run automatically on desktop update. Earlier migrations may already be applied and are not edited.

| PC migration | Purpose |
| --- | --- |
| `20261114120000_sync_change_log` | Independent change log and capture triggers. |
| `20261114180000_sync_change_log_fanout` | Replace trigger functions with bounded, affected-record fan-out. |
| `20261116090000_sync_worker` | Disabled-by-default worker state and permanent action journal. |
| `20261116100000_sync_phone_read_projections` | Request a staged backfill for inventory/financial read projections. |
| `20261117090000_sync_payment_targets` | Request a backfill for customer payment targets. |
| `20261117121000_sync_figure_snapshots` | Persist figure snapshot hashes/progress and backfill role visibility. |

The relay is a separate database. Its automatic deploy applies all six relay migrations: `20261115090000_relay_foundation`, `20261115100000_relay_review_fixes`, `20261116091000_worker_snapshots`, `20261116110000_relay_device_role`, `20261117120000_relay_snapshot_visibility`, and `20261117140000_relay_device_security_status`. No shop connection string belongs in the relay service.

The phone migrates the old plain cloud database into an encrypted one, preserving outbox IDs/payloads/statuses and photos before deleting the old files, then re-downloads record caches. Install over the old APK; do not uninstall first. Existing cloud pairings need PIN setup. LAN credentials remain on their existing path. Changing the PC's JWT secret requires saving its worker secret again.

## Operator checklist

- **Prepare the PC, disabled:** Settings → **Create backup now**; wait for success. Install desktop **2.4.0** and keep **Enable phone cloud sync** off. This preparation is needed because the secret button is new. No phone update yet.
- **Deploy the relay before enabling cloud or installing the APK:** follow the [click-only setup guide](../setup/CLOUD_RELAY_SETUP.md). Create the Neon Free Frankfurt project with fixed **0.25 CU** and five-minute suspension, create/copy the worker secret from Settings, paste the pooled database URL and secret hash into Render, and wait for the health page to show `{"ok":true}`. The build applies relay migrations automatically.
- **Enable the PC:** paste the HTTPS relay address, retain the generated worker secret, set opening hours, enable and save. Click **Sync now** and check **Last sync** with no error.
- **Install and pair:** install phone **2.3.0 / 13** over the old app, create its pairing QR from Settings, set its PIN, and compare a product and customer balance with the PC. Keep the PC running while testing queued actions.
- **Smoke and observe:** complete the [cloud phone checklist](../mobile/release-checklist.md#cloud-release-230-with-pc-240). Review actual Neon compute/storage/transfer usage daily during the first week; local request counts are not CU-hour measurements.
- **Pause/rollback:** uncheck **Enable phone cloud sync**, save, and switch phones to the shop-Wi-Fi connection. This stops PC cloud processing; it does not erase cached phones or stop their relay traffic. Check pending cloud work on the PC before entering it again. Do not uninstall or delete migrations as a rollback.

## Verification

- **Local:** the eight-scenario end-to-end test uses real PC/relay HTTP apps, the real worker and phone sync/outbox code, and disposable PC/relay test databases. Targeted tests and backend/frontend/relay/phone typechecks are recorded in the [Phase 8 review](../cloud-sync-phase-8-review.md), with per-scenario requests/body bytes and limitations.
- **CI:** `test:ci` now enables `RUN_CLOUD_E2E=1` alongside the other database flags. The test refuses unsafe database names and creates its own disposable databases, so restore testing cannot truncate other suites' fixtures. CI needs a local test PostgreSQL role with database-creation permission, as provided by the CI service.
- **Release gate:** Claude runs the full suite after the deferred fixes. Native PIN timing, SQLCipher/biometric/recents smoke checks and actual receipt sharing must be verified on a real phone before distribution. This preparation does not claim an APK build, live deployment or measured first-week provider usage.
