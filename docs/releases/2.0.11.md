# HomeConnect 2.0.11

Multi-branch now works without editing any configuration file.

## Fixes

- **A second branch can be activated from Settings → Branches.** In 2.0.10, activating or creating a second branch was refused with "Branch separation is not released yet. Only one branch may be active." unless a setting was added to `production.env` by hand. That development safeguard is gone: multi-branch is on by default.
- **Confirmation before a second branch goes active.** Settings → Branches now explains what changes (branch selector in the header, separate records per branch, employee access) and asks before activating an additional branch.
- **New employees keep getting the shop's branch automatically** when exactly one branch is active. With two or more active branches, assign each employee's branches in Settings → Branches.

## Migration notes

No database updates. Installations coming from 2.0.8 or earlier also run the five 2.0.10 updates listed in [2.0.10](2.0.10.md).

If `MULTI_BRANCH_SCOPING_ENABLED=true` was added to `production.env` for 2.0.10, it can stay or be removed; it no longer matters. `MULTI_BRANCH_SCOPING_ENABLED=false` limits an installation to one active branch, as an emergency switch only.

## Operator checklist

Beyond the default [upgrade smoke test](upgrade-smoke-test.md):

- Settings → Branches: activate a second branch, confirm the prompt, and check that the branch selector appears in the header.
- Give an employee access to one branch, sign in as that employee, and confirm they see only that branch.
