# HomeConnect 2.0.9

Multi-branch support, customer imports, and safer database restore and update.

## New

- **Branches.** Records belong to a branch. A branch selector in the header switches between one branch and "All branches"; lists show a Branch column in "All branches", and new records are created in the selected branch. Reports and dashboard figures can be compared per branch. With a single branch, the app behaves as before.
- **Dashboard → Branches.** In "All branches": customer debts per branch (outstanding, overdue customers, new debt, collected), cash flow by branch over time, supplier balances per branch in their own table (never netted against customer debt), and links into each branch's reports and ledger.
- **Change a customer's branch** (admins, account password). The customer moves to the chosen branch with all of their history: sales, returns, refunds, credits, payments, debts, installment plans and service jobs. Balances do not change. Everything moves together or nothing moves, and the move is recorded in the activity log.
- **Customer CSV import** into a chosen branch, including trial-balance account imports with opening balances recorded as debts.

## Fixes

- **Restore no longer leaves a half-restored database.** A restore now runs as one transaction: if anything fails, the database stays exactly as it was. Backups made by an older version are restored and then brought up to date automatically. Backups from a newer version are refused.
- **Database updates no longer time out** on larger databases; each update now has up to 30 minutes instead of 5 seconds.
- **"Resolve update history" can no longer mark an update as applied when its tables or columns are missing.**
- **Updates from a clean build** no longer fail with a checksum error on installations whose first database update was recorded with Windows line endings.
- Includes the 2.0.6–2.0.8 update-recovery fixes and the 2.0.7 mobile LAN sign-in fix.

## Migration notes

These database updates run on install, in order, after the automatic pre-update backup:

1. `20261017120000_add_branches`: branches and user branch access.
2. `20261027120000_add_branch_ownership`: every customer, supplier, sale, debt, payment and related record is assigned to a branch. All existing history goes to the single active branch, or to a new "Main branch" if none exists.
3. `20261028120000_add_customer_imports`: customer import drafts.
4. `20261029130000_add_customer_import_accounts`: trial-balance account links.
5. `20261029150000_allow_customer_branch_transfer`: allows the admin branch transfer. It changes no data and drops no constraint.

No manual step is needed afterwards. A second branch can only be activated where `MULTI_BRANCH_SCOPING_ENABLED=true` is set; leave it off on the business PC until multi-branch use is decided.

## Operator checklist

Beyond the default [upgrade smoke test](upgrade-smoke-test.md):

- After the update, open Settings → Database update and confirm nothing is pending, then open Customers, Debts and the Dashboard: totals should match the values before the update.
- Settings → Backups: make a manual backup and check that its restore check says "Compatible database: Yes".
