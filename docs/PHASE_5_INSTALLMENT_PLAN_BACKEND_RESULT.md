## Behavior Implemented

Plan creation:

- customer must exist and be active
- schedule generated by Phase 3 helper
- first installment due on start date
- amount rounding remains Decimal-safe
- plan and installments created in one transaction

Payment:

- one payment may allocate to multiple installments
- allocation uses oldest due date then installment number
- paid/cancelled installments are skipped
- overpayment is rejected
- idempotent retry does not duplicate payment or allocations
- conflicting idempotency returns `409`
- installment `paidDate` is set when payment completes it
- statuses update in the transaction

Cancellation:

- unpaid plans can be cancelled
- plans with valid payments are rejected
- plan and schedule history are preserved
- unpaid/partially paid active installments are cancelled
